# 程序员的最后一个冬天：我看到的是学徒制在结冰

> 发布日期：2026-11-09\
> 标签：职业发展 / AI 编程 / 程序员 / 学徒制 / 工程判断

这个十一月，一句话在微博、掘金和各种群里转得很勤：「程序员迎来最后一个冬天，手搓代码或许要申请非遗了。」

配的画面通常是许愿式编程。对着模型喊一句目的，一个八九不离十的小程序就出来了。评论区很快分成两派。一派说认可，这个行业接下来就没了。一派说去广东上班就没有冬天。

两派都在接梗。我想把这句口号放回工作台上看一看。

我每天用 Agent 写代码，也每天在审它交上来的东西。周一站会上有人把那句「申请非遗」当笑话讲完，下午我就对着一份订单列表的 diff 坐了两个小时。草稿是模型写的，演示账号一路绿灯。无权限的账号打开页面，看到的是「暂无订单」。运营会以为数据丢了。代码能跑。人不敢这么发。

我的判断没有口号那么绝，也没有「春天到了，把 Prompt 练好就行」那么轻。这个冬天确实冷。冷的位置，和传言指的地方不一样。

![屋里已经在出活，学徒还站在结冰的梯子下面](/blogs/images/last-winter/01-hero-frozen-ladder.jpg)

> 屋里的灯亮着，人和机器人已经在出活。梯子结了冰，学徒还在雪里。

这篇想讲清楚四件事：口号里其实是三场冬天；公开数字冷在哪、没冷在哪；学徒制是怎么结冰的；不同的人这个冬天可以做什么。全文大约十五分钟。数字都标明了出处，国内的部分我只写自己看到的现象，不编百分比。

## 一、口号把三场降温揉成了一场

「最后一个冬天」之所以好听，是因为它给焦虑一个结局：要么这个职业到此为止，要么熬过这一季就会回暖。我更愿意把它看成气候变了。旧的生长季被打乱了，季节本身还在。

![三场冬天：手搓退场，学徒结冰，职业还在](/blogs/images/last-winter/02-three-winters.jpg)

> 退场的是手搓。结冰的是学徒。第三格那块纸板是空的，办公室里的人和机器人都还在干活。灭绝是口号后补上去的。

拆开之后，其实是三层降温。我认前两层。

| 口号里的句子 | 我在工位上看到的 |
| --- | --- |
| 手搓代码要申请非遗 | 样板代码在退场，阅读和签字没有退场 |
| 这是最后一个冬天 | 旧的长大方式正在过冬，季节还会再来 |
| 后面没有这个行业了 | 招聘还在，门变窄了，责任变重了 |
| 会许愿就会编程 | 会提问、会拒绝、敢签字，才接得住草稿 |

**第一层：手搓作为主要劳动，正在退场。**

把已经说清楚的需求翻译成样板代码，曾经占掉程序员一天里很大一块时间。一个标准表单，对齐字段、补校验、接接口、调间距，以前要半天。现在把字段表和三条约束丢给模型，咖啡还没凉，骨架就在了。小工具、活动页、增删改查、测试骨架，都属于这一层。

说「古法手搓要申请非遗」，作为段子，它抓住了真实体感。我也不会假装自己还在手写每一个输入框。键盘从「产量工具」变成了「偶尔亲手确认手感还在」的工具。这一层的退场，我认。

**第二层：入行的那截梯子，正在结冰。**

新人过去靠改简单缺陷、补边界、照着旁边的页面做一个很像的列表，慢慢看见整套系统。这些活琐碎，也是职业训练。

我记得自己第一次真正记住「接口成功不等于有数据」，不是在分享会上。是一张很傻的票：空列表要把文案从「加载失败」改成「暂无订单」。改到一半发现，没权限的时候后端也返回一段看起来很成功的 JSON，页面把两种情况画成了同一句话。用户来问「我的单呢」。那张票做完，我才知道要先问后端：`code`、`success`、空数组、`data: null`，四件事各自是什么意思。

模型现在正好擅长这种票。企业少招专门做这些活的人，短期报表更好看。新人少了一条「先上手，再长出判断」的路。这一层的结冰，我认，而且比第一层更要紧。

**第三层：程序员这个职业，会在这个冬天结束。**

这一层是口号多出来的。软件还在被人使用，还在出事，还在被追责。需要人的地方，从「把字敲进去」挪到了「决定什么能进主干，出了问题谁来扛」。岗位结构在变。需求并没有按灭绝的曲线在走。

把第三层当成事实，会推出两种糟糕决定。一种是立刻逃离一个仍在招人的行业。一种是觉得手搓已经进了博物馆，从此不再读代码。两件事都比这个冬天本身更伤。第一种把周期波动当成了绝路。第二种把鉴别力交了出去，而鉴别力正好是这个冬天还值钱的东西。

## 二、体感很冷，数字没那么绝

把话说满之前，先看 2026 年已经公开的几组数字。它们来自不同样本，不能拼成「AI 消灭了百分之多少程序员」。方向够用。国内的体感还要再叠一层，这个我放在本节最后。出处在文末。

![以前的一天耗在敲，现在的一天耗在审](/blogs/images/last-winter/03-time-moved.jpg)

> 左边那一摞是敲出来的。右边那一摞是盖过章的。钟都走到了同一格，人没有因此闲下来。

澎湃新闻在 2026 年程序员节前后，报道了技术服务公司 BairesDev 对 705 名软件开发者的调查：

| 调查里发生的事 | 大致比例 |
| --- | --- |
| 平均每周少花在编程上的时间 | 约 13 小时，差不多是一年前的两倍 |
| AI 已经参与编写至少一半代码 | 42%，一年前是 12% |
| 每周仍有一半以上时间在写新代码 | 21% |
| 审查 AI 代码的时间变多 | 67% |
| 要花更多精力寻找不明显的错误 | 近六成 |
| 对并非完全自己写下的代码感到责任更重 | 58% |
| 感到「交付得更快」的压力变大 | 超过一半 |
| 每周至少省下 6 小时，同时又在学新工具 | 约三分之二省下了时间；近三成每周学工具超过 10 小时 |

这张表里最容易被读错的是第一行。少花 13 小时在编程上，不等于多出 13 小时生活。同一批人里，六成以上花了更多时间审查，近六成花更多精力找那些不明显的错，超过一半感到交付变快的压力，近三成每周还要再投 10 小时以上去学工具。省下来的时间换了岗位，没有离开岗位。

剩下那 21% 仍把一半以上时间用来写新代码的人，写的往往也不是样板了。样板已经被模型拿走。还留在手里的，是边界、状态和「这次到底做什么」。

招聘侧也不是一条直线往下。CNBC 今年 10 月引述 Indeed Hiring Lab：美国软件开发职位的招聘信息，自 2025 年 2 月底以来上升了近 15%，同期美国整体职位招聘下降约 7%。回升集中在有经验的位置上。2025 年 5 月到 2026 年 5 月的增长里，大约 71% 来自高级职位，大约 37% 来自标题里带 AI 的职位。这两个比例会重叠，不能加成 108%。即便这样，软件开发招聘距离疫情前的水平，仍低了大约 27.5%。更早的那一截下滑，也不全是模型造成的。2022 年招聘高峰过去之后，公司本来就在收缩。

年轻人这边，数字冷得多。

![22 到 25 岁下降近两成，41 到 49 岁上升近两成](/blogs/images/last-winter/07-age-split.svg)

斯坦福数字经济实验室和 ADP 的就业指数，以 2022 年 11 月为基期，到 2026 年 8 月，22 到 25 岁的软件开发者下降近两成，41 到 49 岁上升近两成。这是使用 ADP 发薪服务的美国企业样本，不是全美劳动力市场的全貌，也不能把变化全部算到 AI 头上。斯坦福《2026 年人工智能指数》里另一组相关数字是：生成式 AI 兴起之后，22 到 25 岁、从事 AI 暴露较高工作的就业下降约 16%；其中早期软件开发者的降幅大约 20%，年长开发者的岗位在扩张。

往远了看，美国劳工统计局 8 月的报告仍给出增长：2025 到 2035 年，软件开发人员就业大约从 172 万增到 189 万，增幅约 10%。

这几组数放在一起，站得住的结论只有两句。职业总量按灭绝来讲，公开数据不够。初级岗位的门变窄，已经写在分年龄的就业数字里。

### 这些数字在我的一天里长什么样

调查是别人的样本。我能负责的，是自己的工作日。下面不是打卡记录，是 2023 年和 2026 年两段典型下午叠在一起之后的样子。

| 时间 | 2023 年，模型还帮不上这种忙 | 2026 年，草稿来得很快 |
| --- | --- | --- |
| 9:30 | 看接口文档，自己起表格 | 先写一页约束：做三个筛选，不做导出，不做批量 |
| 11:00 | 还在对列宽和字段 | 草稿已经在了，开始读 diff |
| 14:00 | 调样式，补加载 | 对着真实错误码，删掉模型多加的导出 |
| 16:30 | 空态常常来不及，先发快乐路径 | 补无权限用例。这条用例草稿里没有 |
| 19:00 | 觉得自己写了很多行 | 行数不多。签字的是整页在失败时的行为 |

行数变少了，下班没有因此变早。变早的是「看起来能演示」的那个时刻。变晚的是「我愿意让它进主干」的那个时刻。BairesDev 调查里「审查变多、责任变重、交付预期变高」，在我这里就是这张表。

### 国内的冷，是两股风叠在一起

上面全是美国劳动力市场的数字，不能直接当成国内校招和社招的精确画像。国内这几年的冷，至少有两股风叠在一起。

第一股从 2022 年前后就开始了。互联网收缩，校招变少，外包先停，一个人被期望干过去一个小组的活。那时候模型还交不出一个能用的小程序。这股冷是周期和行业出清。把它全部算进「AI 这个冬天」，会高估模型，也会低估那几年已经发生的裁员和 HC 收缩。

第二股是 2025、2026 年，生成式模型真的开始吃掉初级实现。我在团队和面试里看到的变化很具体，这里没有全国统计，只是我自己的样本：

- 岗位标题从「熟练某个框架」写成「能独立负责，熟练使用 AI 编程」。
- 笔试里手写题还在。决定要不要继续聊的，往往变成：你怎么发现模型写错了，你拒绝合并过什么。
- 群里转发的热点，从框架大版本换成了「最后一个冬天」。同一周里，有人在焦虑转行，有人在比谁的 Agent 一晚上能开多少文件。

口号把两股风叫成一个名字，于是所有不顺都像是模型带来的。拆开才好判断。周期会回一些，也可以再差一些。工作内容的更换不会跟着财报季度原路退回。样板代码被拿走这件事，不会因为下一次校招多了就自动把学徒制还回来。

## 三、我担心的是学徒制，不是键盘

一个职业要延续，得有人从生手变成能负责任的人。过去这条路很笨，也很有效。

新人先做模型现在最擅长的那些事。做着做着，判断才长出来。这些判断不是课程。它们是初级任务的副产品。

| 过去的初级任务 | 当时顺便学会的事 | 现在多半谁在做 |
| --- | --- | --- |
| 改一处文案 | 这句话和权限、空数据、失败是不是一回事 | 模型 |
| 补一个判空 | 接口返回成功，不代表有数据 | 模型 |
| 照着邻页做一个列表 | 这个列表为什么不能一次拉完 | 模型 |
| 跟着报错翻一段旧代码 | 哪段历史不能动，为什么 | 越来越少的人 |
| 跟一次发布或一次事故 | 用户先看见什么，谁被叫起来 | 还是人，但新人常常不在场 |

顺序很重要。人不是先学会「对结果负责」，再去碰那些无聊的票。人是在无聊的票里，第一次看见责任长什么样。票没了，责任还在，中间的台阶就空了。

AI 把副产品的载体拿走了一大块。企业如果只留下「两个老人加一排 Agent」，这个季度可以交付更多。十年后的老人从哪来？

Indeed Hiring Lab 的经济学家 Sneha Puri 说得很直：今天的初级人才，就是明天的资深专家。现在不留通道，十年后就没有你需要的那种资深。

这件事比「还会不会写 for 循环」严重。for 循环模型会写。系统为什么长成现在这样，什么情况下不能信它，事故之后怎么收场，这些仍然要有人在真实系统里长出来。一个只在教程和 Prompt 里长大的人，不是不能学会。是他缺少那些「当时觉得很傻、事后变成直觉」的下午。直觉没法在发布说明里下载。

同一道裂缝也会出现在别的行业。年轻记者从核对材料里学判断，初级律师从检索和整理卷宗里熟悉业务。初级劳动既是产出，也是训练。把训练一起自动化掉，组织会在若干年后发现，自己买不到「有判断的老人」。老人本来就是被那些无聊任务喂大的。

我把这叫做学徒制结冰。冬天会过去。结冰的河道，不会因为一句口号喊完就自己开河。

## 四、「手搓申请非遗」是好笑话，是坏计划

日常工作里，许愿式编程已经是事实。目的说清楚，模型能给一个八九不离十的起点。笑话从这里开始变质。有人听见「手搓要申请非遗」，就以为阅读和编写代码可以一起捐进博物馆。

审查变多了，责任变重了，交付预期也变高了。三件事叠在一起，对读不懂代码的人更苛刻。你要在更短的时间里，对更多不是自己打下的字符负责。本钱只有一样：你仍然看得出它错在哪。

![草稿看起来已经完成，人还在看空态、权限和失败](/blogs/images/last-winter/05-read-the-diff.jpg)

> 机器人觉得这页可以交差了。人还在空态、权限和失败这三张条子上打转。这三张条子，就是现在的手艺。

### 一次「能演示」的订单列表

下面这段不是某家公司的原始事故记录。它是我把最近几次评审里反复出现的坑，收成一个能看懂的例子。演示账号是管理员，有数据。模型按常见的成功判断把页面接上了。

后端在没权限时仍然返回 HTTP 200，包体是这样的：

```json
{
  "code": "200",
  "success": false,
  "msg": "无权限",
  "data": null
}
```

草稿里的加载函数：

```ts
async function loadOrders(query: OrderQuery) {
  const res = await fetchOrders(query);
  if (res.code === '200') {
    const list = res.data.list;
    setOrders(list);
    setEmpty(list.length === 0);
    return;
  }
  setError(res.msg);
}
```

演示的时候，管理员账号 `code` 是 `'200'`，`success` 是 `true`，`list` 里有单。页面是对的。评审如果只看这个账号，会通过。

没权限的运营一打开，三件事情叠在一起：

1. `code` 仍然是 `'200'`，`success` 却是 `false`。代码走进了成功分支，没有走进 `setError`。
2. `data` 是 `null`。读 `res.data.list` 会直接抛错。如果这层没有兜住，屏幕上留下来的是上一次筛选的订单。换个说法，一个没权限的人可能看见别人的单。
3. 就算有人先写成 `res.data?.list ?? []`，`list.length === 0` 也会把「没权限」画成「暂无订单」。运营的第一反应是数据丢了，不是自己没权限。

测试同学用的也是有数据的账号。这条路径不在用例里。模型没有错在「不会写列表」。它错在用互联网上最常见的成功判断，猜了一套我们后端并不是那样的约定。

我在这种 diff 上会留的评论大体是：

> 无权限时接口仍然 `code = "200"`、`success = false`、`data = null`。现在要么抛错留住旧数据，要么被画成「暂无订单」。请把三种状态分开：有数据、真的为空、没权限或失败。补一条无权限的测试，演示账号覆盖不到。

这就是「会跑，但下一个人不敢碰」。我在 [别急着 Vibe Coding](/blogs/post/7ac40b98745f4162) 里写过一次更完整的翻车：活动页一个下午交卷，修到第三天，将近一半文件删掉重写。原因通常也很具体。边界用含糊的类型糊过去了。空态、权限态、失败态停留在快乐路径上。抽象多了三层，没有一处是这个需求需要的。[生成代码之后审什么](/blogs/post/87ba83ff160a44ba) 那篇把评审清单写得更细。这里只强调一件事：看得出来的前提，是你自己写过、改过、背过锅。那口锅，以前常常是初级任务送给你的。

所以有几件老派的事，我打算继续做：

1. 模型可以起草。合并前，我要能读完 diff。
2. diff 大到读不完，这次改动就还不能进主干。谁打的字，不改变这条。先把改动拆小，而不是先培养「大 diff 也能赌」的习惯。
3. Prompt 写得漂亮，不能代替「这个改动上线之后谁被叫起来」。叫起来的那个人如果答不出无权限时长什么样，这页就还没做完。

编程知识在这里换了一个角色。它从产量变成了鉴别力。鉴别力没有捷径，仍然来自你在真实约束里写过、读过、错过。

## 五、挨冻的人，和只是换了件衣服的人

同一句「最后一个冬天」，落到不同人身上，温度差很大。

![应届、三年、资深、团队，站在同一场雪里](/blogs/images/last-winter/04-four-temperatures.jpg)

> 同一种天气，四个人的装备不一样。最右边那口炉子把季报烧旺了，倒进去的口袋上写着种子。

**应届生和转行第一年的人最冷。** 招聘回升主要在高级职位，以及标题里带 AI 的职位上。作品集如果只证明「我能把教程做出来」，而教程级产出正好是模型的舒适区，那份作品集是在证明一件市场正在打折的能力。

这个冬天更有用的作品，是一个小系统，外加一页你自己的评审记录：模型起草了什么，你拒绝了什么，用户在没权限、为空、超时的时候分别看见什么，哪条测试是你补上的。面试官想看的不是你打过多少字。是你能不能在草稿看起来很完整的时候，仍然发现那三张条子。

**做了三五年、身份是「在某个框架里关票很快」的人，冷在中间。** 语言需求已经在分化。Lightcast 整理 2015 到 2026 年软件工程师招聘里最常出现的技能，Python 的提及率从大约 14% 升到大约 41%，一部分传统开发语言的提及率在回落。这不是号召大家都去改行 Python。这是说，只守着一种语法的手速，议价会变差。

还能搬走的，是你对一条真实链路的理解：状态从哪来，失败怎样回到用户面前，哪个接口的「成功」不能信，哪次发布之后你值过班。把这条链路写成一页约束，比再刷一个新框架的待办列表更抗冻。约束怎么写，我在 [一页 Spec](/blogs/post/a9c5d420b4584dd3) 里写过。那里的重点不是文档仪式，是不让模型替你把没说的需求也做了。

**资深的人不是穿着羽绒服看戏。** 同一次调查里，有经验的工程师被放大了：一个人加上模型，能覆盖过去一个小组的一部分活。放大的同时，爆炸半径也变了。你签过字的代码更多，其中亲手写的比例更低。资历保护不了「我不看 diff」。它只让失误变得更贵。

资深工程师这个冬天最容易偷的懒，是把审查变成点头。草稿风格统一、类型能过、演示能点，手就松开了。松开几次之后，团队会以为你在把关，其实你在透传。透传的人一旦休假，系统就进入「能跑，没人解释」。

**还有一种组织在主动受冻。** 砍掉初级名额，留下几个老人喂 Agent。下个季度的吞吐量可能很好看。知识开始只活在两个脑子里，和一堆没人敢重构的生成代码里。老人一休假，没人讲得清为什么无权限不能画成空列表。这是把种子粮当成了口粮。季报上的箭头可以向上。十年后能签字的人，不会从这口炉子里长出来。

## 六、还想在这个行业过冬，我会做的几件事

我不准备开一份「三个月转行 AI 架构师」的清单。那种清单和「最后一个冬天」是同一类内容：都在卖一个干脆的结局。

我自己在做的，更窄，也更能天天执行。

**每周留两小时，不完全交给 Agent。**

不是为了和模型比手速，是为了保住鉴别力。这两小时可以是一段你在意正确性的逻辑，一次事故复盘，一份你亲手收过口的接口。手感断了，Review 会退化成「看起来挺像那么回事」。我给自己的最低标准是：这周至少有一个合并进主干的改动，里面有我自己写的失败分支，而不是只改了模型的变量名。

**把价值从字符挪到约束。**

需求进来，先写清做什么、不做什么、怎样算失败、谁在用、数据从哪来、坏了怎么回滚。订单列表那个例子里，只要事先写了一句「无权限、空列表、请求失败是三种界面」，草稿就很难把它们画成同一句话。Agent 返工多，常常是因为这页纸不存在，它就只好猜。猜对了像魔法。猜错了像事故。

**用能被检查的方式使用 AI。**

提交说明里写清哪部分是模型起草的，你改了什么，你还没验证什么。让同事看见你的边界。会用工具已经是起点，不再是差异点。差异点是你愿不愿意把不确定的部分亮出来。

```text
草稿：Agent 生成了订单列表的请求、表格和空态
我改了：无权限不再画成「暂无订单」；data 为空时不再读 list
删了：导出和批量操作，这次需求没有
还没验证：弱网下的重试。准备明天用限速再走一遍
```

这样的说明比「AI 辅助完成」有用。后者什么也没说。前者告诉下一个读者，哪里可以信，哪里还不能信。

**如果我在带人，我会把训练故意留在流程里。**

初级任务可以交给模型。初级判断不能。我愿意固定一块三十分钟，每周一次，不评绩效，只做这件事：

1. 挑一段本周要合并的 diff，主要不是作者手写的，控制在大约两百行以内。读不完的先拆。
2. 作者先讲：模型假设了什么接口约定，哪条假设还没问过人。
3. 另一个人只问三个问题。它假设了什么？哪条假设在我们的系统里不成立？如果它错了，用户先看见什么？
4. 散会前记下一条要补的测试，或者一句要写进下次约束的话。

CRUD 的票，模型已经会了。提问的习惯，替学徒长不出来。三十分钟看起来很少。它是在那些已经被拿走的练手票旁边，重新挖一条窄通道。窄，但是通的。

**找工作时看通道，不看口号。**

一个团队如果只招「三年以上，熟练使用 Agent，能独立负责」，却不解释那三年从哪来，它是在消耗行业，也在消耗你。我如果坐在面试的另一边，会问这三句：

- 你最近一次拒绝合并模型写的代码，理由是什么？请讲到用户会看见什么。
- 新人前三个月，和谁一起看 diff？还是只看演示？
- 上次线上问题里，有没有一次「接口看起来成功，业务其实失败」？谁先发现的？

答得出来的团队，通道还在。三句都滑过去的团队，报销不报销 Cursor，说明不了什么。

沟通、把事情推过部门墙、在压力下说「这个不能发」，这些能力在招聘建议里被反复提到。代码变得便宜之后，让人愿意相信你的判断，就变成了硬通货。说「不能发」的底气，仍然来自你读过那段代码，而不是来自你更会担心。

## 七、这个冬天会过去，学徒制要有人去凿

季节被人拿来比喻太多次了。有一处它仍然准：冬天不是永夜。说「最后一个」，是把一次结构变化说成了灭绝倒计时。倒计时会让人要么躺下，要么慌着买下一门课。结构变化要求的是另一件事。看清哪段旧路断了，然后把新路铺到自己脚下。

![黎明前，把结在冰里的代码一点点凿开](/blogs/images/last-winter/06-chisel-the-ice.jpg)

> 冰不会因为一句口号转发完就开。河道是顺着那些还愿意看懂的代码，一点一点凿出来的。

我看到的断路，是「靠初级劳动自然长成资深」这一条。

新的路不会自动出现在模型的下一版发布说明里。它大概是这样：起草可以很快，合并必须可读；一个人的杠杆可以很大，团队里仍要有人从生手被带成能负责任的人；语法会贬值，对具体系统的理解不会。

手搓代码不会变成非遗。它会变成一种不再按行数计薪、但在关键处离不开的基本功。像司机不必自己造发动机，仍得会在失控时把车稳住。稳住需要的不是把每一颗螺丝亲手造出来。是你还认得方向盘，还认得冰面。

门外的风是真的。屋里要做的事也很具体：把 diff 读完，把无权限和空列表分开，每周留出那三十分钟，然后对你签过字的结果负责。

旧的长大方式，正在过它难熬的一年。接下来的日子，只会长在你还愿意看懂的那些代码上。

# 别再左右滑了：我做了 13 种「能摸」的看图方式，用户才愿意停下来

> 发布日期：2026-08-03\
> 标签：前端 / React / 交互设计 / 活动页 / CSS 3D / Canvas / 用户体验

产品经理说：「这组图很重要，一定要让用户看完。」

你打开文档，复制一段 Swiper：左右箭头、指示点、`autoplay: true`。上线第二天数据回来——停留几秒，滑了半张，走了。

不是图不好看。是交互太像「任务」：用户一眼就知道这是广告位，身体已经学会跳过。人脑对任务默认逃，对**桌上能摸的物件**默认会上手玩一下。

这篇文章想讲清楚一件事：

> **看图不一定要用轮播。把图集还原成相册、晾绳、胶卷、走马灯……用户记住的是手感，不是第几个指示点。**

全文大约 15 分钟。建议按这个顺序读完，收益最大：

1.  为什么轮播留不住人（心智，不是特效）
2.  物件隐喻的三条设计原则（你自己做也能用）
3.  五个最容易种草的玩法（含「适合 / 别用」）
4.  其余 8 个怎么挑、三个完整页面配方
5.  五分钟接入、常见翻车、性能与移动端注意点

实现开源在 [cos-design](https://github.com/jiaxiantao/cos-design) 图片预览分类（v3.7.3，13 个组件）。你可以当现成组件用，也可以只抄交互思路——两种读法都成立。

## 一、轮播没罪，是用错了场景

先把话说清楚——**Swiper 仍然是好工具**。电商详情、后台附件、信息流多图，轮播就是正解：快、轻、指标友好。

活动页、婚礼邀请、旅行回顾、品牌故事要的是另一件事：**注意力停留**。这两类目标，评价指标都不一样。

| 维度 | 信息浏览型图集 | 叙事停留型图集 |
| --- | --- | --- |
| 成功标准 | 切得快、转化路径短 | 愿意多玩一会、愿意转发 |
| 典型交互 | 左右滑、指示点、自动播 | 翻、甩、卷、转、穿行 |
| 用户心智 | 「这是广告 / 任务」 | 「这是桌上的东西」 |
| 摩擦 | 越少越好 | 适量摩擦 = 玩法 |
| 代表方案 | Swiper / 原生横滑 | 物件隐喻组件 |

我见过很多次「活动页图很好、文案也好，就是没人看完」。复盘时大家往往去改文案、加自动播、加更大的箭头——很少有人怀疑：**交互隐喻本身就在劝退**。

轮播的隐喻是「幻灯片」。会议室、答辩、周会——人已经练出「看到指示点就想跳过」的反射。物件隐喻则不同：相册要翻、晾绳要甩、胶卷要卷、磁贴要挪。身体知道下一步怎么做，大脑才会愿意多停几秒。

一句话选型：

> **列表层继续用轮播；高潮段落换成物件。** 页面立刻有层次，也不用推翻整站。

读到这里如果你只记住这一句，后面的组件介绍都会变成「工具箱」，而不是「又一个特效库」。

## 二、物件隐喻为什么管用：三条可复用原则

做完 13 个组件后，我发现真正可复用的不是 CSS 技巧，而是三条原则。自己从零写 Demo，也可以按这个检查。

### 原则 1：一眼能叫出名字

用户不需要读「拖动以浏览更多图片」。他应该下意识说出：「哦，这是一本相册 / 一根晾绳 / 一卷胶片。」

叫不出名字，就说明外形还不够像，或者像了但手感不像。**名字 = 心智快捷方式。**

### 原则 2：动作要对得上真实世界

| 物件 | 用户预期动作 | 如果做成…就会违和 |
| --- | --- | --- |
| 相册 | 点右页往后翻、点左页往回翻 | 左右无限循环轮播 |
| 晾绳 | 抓住照片往外甩，松手摆回 | 只能点左右箭头 |
| 胶卷 | 横拖有惯性，松手吸到整帧 | 松手停在半帧 |
| 明信片 | 能翻面看背面寄语 | 只有正面大图 |
| 冰箱磁贴 | 拖走就停在新位置 | 松手弹回原点 |

手感对了，用户会自己探索；手感错了，再华丽的材质球也像 PPT。

### 原则 3：故事气质要匹配页面

婚礼页挂走马灯、后台表格旁塞翻页相册——都会显得「为特效而特效」。选型时先问气质，再问技术栈：

*   仪式、纪念、年鉴 → 相册、卷轴、明信片
*   生活、轻松、可乱摆 → 拍立得、冰箱、晾绳
*   复古、电影、帧序列 → 胶卷、灯箱
*   展台、夜场、六面叙事 → 走马灯、棱镜
*   品牌大片、沉浸开场 → 隧道

三条原则可以压成一句自检：

> **叫得出名字、动作对得上、气质配得上——三件事同时成立，物件隐喻才成立。**

## 三、五个最容易种草的玩法（建议逐个点开试）

不必一次学完 13 个。先把下面五个摸熟，覆盖大多数活动页。每个都写清：**它是什么、适合什么、别乱用、试玩入口**。

完整 Props 以 Playground 与 [docs/ai.md](https://github.com/jiaxiantao/cos-design/blob/main/docs/ai.md) 为准。

### 1. PhotoAlbum：真的能翻的相册

摊开左右页。点右半边往后翻，点左半边往回翻；铁圈、书脊谷影、飞页开场都在。底层不是「每张图挂一个 `rotateY`」，而是 **一叶两面** 的状态机：翻走的是「当前右页 + 它的背面」整叶，索引每次 ±2，翻到过半再卸层，中缝才不闪。

**适合**：婚礼、周年、旅行终章、品牌年鉴——需要「开场 → 翻阅 → 收束」的段落。

**别乱用**：图很多、用户只想快速扫货时；相册适合「慢慢看」，不适合「秒切 50 张」。

试玩：[PhotoAlbum](https://jiaxiantao.xyz/cos-design/#/photoAlbum)  
实现深挖：[CSS 3D 翻页相册技术实现](https://jiaxiantao.github.io/blogs/post/29f31a0c5fc3461f)

```bash
pnpm add @cos-design/photo-album
```

### 2. PhotoClothesline：能甩的晾绳

照片挂在麻绳上。抓住任意一张往外甩，吊带跟着弯；松手像吊牌一样摆回。空白处左右拖，看更多照片。这里的关键不是「能显示图片」，而是 **甩一下本身就是内容**——很多人会连续甩两三次，停留时间自然上去。

**适合**：生活感品牌页、户外活动、轻松个人站、需要「可玩分享」的段落。

**别乱用**：严肃商务汇报、强转化的首屏 CTA 区。太好玩会抢主按钮的注意力。

试玩：[PhotoClothesline](https://jiaxiantao.xyz/cos-design/#/photoClothesline)

```bash
pnpm add @cos-design/photo-clothesline
```

### 3. PhotoFilmstrip：胶卷条

齿孔、帧号、横向卷动；松手吸附到整帧。电影感很强，尤其适合「一连串时间线」而不是「单张英雄图」。

**适合**：摄影作品集、复古活动、短片幕后、品牌时间线横条。

**别乱用**：竖图为主、文案很长的场景。胶卷是横扫隐喻，竖构图 + 大段说明会挤。

试玩：[PhotoFilmstrip](https://jiaxiantao.xyz/cos-design/#/photoFilmstrip)

```bash
pnpm add @cos-design/photo-filmstrip
```

### 4. PhotoLantern：六面走马灯

Three.js 灯体 + 内光摆动，空闲可自转，拖拽跟手带惯性。它是系列里偏「展台感」的一个：适合产品六面、夜场、展会。

**适合**：夜场 Landing、展会互动屏、产品六面叙事（建议准备约 6 张主视觉）。

**别乱用**：弱网 H5 首屏、对包体积极敏感的活动。它依赖 Three.js，比纯 CSS 组件重，务必按需动态导入。

试玩：[PhotoLantern](https://jiaxiantao.xyz/cos-design/#/photoLantern)

```bash
pnpm add @cos-design/photo-lantern
```

### 5. PhotoTunnel：纵深隧道

沿 Z 轴叠帧，上下（或前后）拖拽穿行，近清远虚，松手吸附整帧。它解决的是「怎么让用户感觉走进故事」，而不是「怎么切下一张」。

**适合**：品牌大片序章、沉浸式开场、需要冲击力的首屏叙事。

**别乱用**：信息密集的说明页。隧道占注意力很凶，后面如果立刻接表单/下单，节奏会断层——中间最好留一个过渡段。

试玩：[PhotoTunnel](https://jiaxiantao.xyz/cos-design/#/photoTunnel)

```bash
pnpm add @cos-design/photo-tunnel
```

## 四、其余八个：各有各的脾气

| 组件 | 一句话脾气 | 你何时会想起它 |
| --- | --- | --- |
| `PhotoPolaroid` | 桌面散落的拍立得，可拖可翻找 | 想要「乱中有序」的生活感 |
| `PhotoFridge` | 冰箱磁贴，拖走就吸在新位置 | 家居、亲子、可长期摆弄的墙 |
| `PhotoPostcard` | 正反翻转 + 邮戳，横拖换下一张 | 旅行寄语、正反两面文案 |
| `PhotoScroll` | 中式手卷，木轴 + 宣纸横拖吸附 | 国风、文博、手账、长卷叙事 |
| `PhotoLightbox` | 透光幻灯片，拖出切换 / 未过阈值弹回 | 展陈、摄影、暗房气质 |
| `PhotoCarousel` | 照片立在圆盘边缘环绕 | 玩具感、展柜托盘、圆形陈列 |
| `PhotoPrism` | CSS 3D 六面贴图翻滚 | 想立体、但不想上 Three.js |
| `PhotoViewMaster` | View-Master 风格转盘切景 | 复古玩具、景点回顾、趣味切景 |

选型时可以再压一版经验法则：

*   **张数少、要讲故事** → Album / Postcard / Scroll
*   **张数中等、要翻找** → Polaroid / Fridge / Clothesline
*   **张数固定六面左右、要立体** → Lantern / Prism
*   **要纵深冲击** → Tunnel
*   **要横条扫描感** → Filmstrip
*   **要「翻面看背面」** → Postcard（文案型）/ Polaroid（翻找型）

## 五、三个完整页面配方（可以直接交给设计一起聊）

选型别先问「CSS 还是 Three.js」，先问「每一段想给人什么物件感」。下面三个配方我自己复用最多。

### 配方 A：婚礼 / 纪念日邀请函

| 段落 | 组件 | 作用 |
| --- | --- | --- |
| 开场 | PhotoAlbum | 仪式感，慢慢翻，建立「这不是广告」的预期 |
| 生活碎图 | PhotoPolaroid | 像桌上翻找照片，轻松、亲密 |
| 祝福收尾 | PhotoPostcard | 正反面写寄语，天然适合「留给你们的一句话」 |

**节奏提示**：Album 不要塞 30 张。8～16 张「一叶两面」节奏最好；碎图交给 Polaroid。

### 配方 B：旅行回顾 / 个人站作品

| 段落 | 组件 | 作用 |
| --- | --- | --- |
| 横条扫过 | PhotoFilmstrip | 像过胶卷，建立时间线 |
| 旅途手记 | PhotoScroll | 长卷叙事，适合配短句 |
| 可玩收尾 | PhotoClothesline | 分享欲强，停留自然变长 |

**节奏提示**：Filmstrip 适合「选帧」；Scroll 适合「读一句 + 看一张」；Clothesline 适合让用户自己玩，别再叠自动播。

### 配方 C：品牌活动 / 夜场 Landing

| 段落 | 组件 | 作用 |
| --- | --- | --- |
| 首屏 | PhotoTunnel | 走进故事，冲击力 |
| 产品六面 | PhotoLantern 或 PhotoPrism | 展台感；要轻量就用 Prism |
| 氛围底 | SmokeFog / Aurora 等 | 情绪层，别抢物件本身 |

**节奏提示**：Tunnel 之后留半屏文案或产品卖点过渡，再接 Lantern；否则用户还在「穿行兴奋」里，看不进字。

气质对照表（速查）：

| 你想表达的气质 | 优先试试 |
| --- | --- |
| 仪式感、慢慢翻、有开场收束 | **PhotoAlbum** |
| 国风、文博、手账、长卷叙事 | **PhotoScroll** |
| 旅行寄语、正反两面文案 | **PhotoPostcard** |
| 复古胶片、电影感帧序列 | **PhotoFilmstrip** |
| 轻松家居、可乱摆的生活感 | **PhotoPolaroid** / **PhotoFridge** |
| 户外晾晒、可玩互动墙 | **PhotoClothesline** |
| 科技展台、立体灯体、夜间氛围 | **PhotoLantern** / **PhotoLightbox** |
| 玩具感、圆形陈列、展柜托盘 | **PhotoCarousel** / **PhotoViewMaster** / **PhotoPrism** |
| 沉浸穿行、品牌大片序章 | **PhotoTunnel** |

## 六、五分钟接入：同一份数据，换外壳

系列刻意对齐数据形状——这是工程上最省事的一点。换组件几乎只改 import，产品试错成本很低：「这版像相册还是像明信片？」改一行就能对比。

```ts
type PhotoItem = {
  src: string;
  alt?: string;
  title?: string;
  description?: string;
};
```

```tsx
import { PhotoPostcard } from 'cos-design';
// 或：import { PhotoPostcard } from '@cos-design/photo-postcard';

const photos = [
  {
    src: 'https://images.unsplash.com/photo-1500530855697-b586d89ba3ee?auto=format&fit=crop&w=800&q=85',
    title: '在路上',
    description: '把远方装进明信片'
  },
  {
    src: 'https://images.unsplash.com/photo-1501785888041-af3ef285b470?auto=format&fit=crop&w=800&q=85',
    title: '山谷晨光',
    description: '风从群山之间吹来'
  }
];

export function TravelPostcards() {
  return <PhotoPostcard photos={photos} ariaLabel="旅行明信片" />;
}
```

```bash
# 试玩最快
pnpm add cos-design

# 上线更干净：只装用到的
pnpm add @cos-design/photo-album @cos-design/photo-clothesline
```

Next.js 建议动态关闭 SSR（浏览器交互为主）：

```tsx
import dynamic from 'next/dynamic';

const PhotoAlbum = dynamic(
  () => import('@cos-design/photo-album').then((m) => m.PhotoAlbum),
  { ssr: false }
);
```

`PhotoLantern` 依赖 Three.js，同样按需动态导入，避免拖慢首屏 JS。

同一份 `photos` 换三种外壳，方便和设计一起拍板：

```tsx
import { PhotoAlbum, PhotoFilmstrip, PhotoFridge } from 'cos-design';

<PhotoAlbum photos={photos} width={780} height={475} />
<PhotoFilmstrip photos={photos} height={280} showCaption />
<PhotoFridge photos={photos} height={420} />
```

## 七、六个常见翻车（我自己或同事踩过）

### 1. 整页堆满物件隐喻

相册 + 晾绳 + 走马灯 + 隧道同一页轮番上阵，和「满屏自动播」一样吵。用户会审美疲劳，也不知道该停在哪。

**建议**：一页 **1～2 个** 高潮物件够了，其余用普通排版或轻量轮播。

### 2. 气质错配

后台工单详情塞翻页相册；严肃招股书风格页挂晾绳甩照片。技术上能跑，品牌上像恶作剧。

**建议**：先写一句话气质（仪式 / 生活 / 电影 / 展台 / 沉浸），再选组件。

### 3. 图太多，隐喻被撑破

相册塞 60 张、胶卷塞 200 帧，手感会从「翻物件」退化成「累」。

**建议**：叙事段控制张数；更多内容用「查看全部」落到列表页。

### 4. 自动播 + 物件手感互相打架

用户正在甩晾绳，自动播又把下一张切走——像有人抢走他手里的照片。

**建议**：高潮物件默认 **关掉 autoplay**；若必须自动，也要在用户操作后立即停。

### 5. 首屏就上最重的 Three.js

Lantern 很帅，但首屏 JS / GPU 压力大，弱网直接劝退。

**建议**：首屏用 CSS 方案（Album / Tunnel / Filmstrip 等），Lantern 放到第二屏或交互触发后再加载。

### 6. 只有快乐路径

图裂了、加载慢、0 张图、文案超长——这些状态不做，上线后最尴尬。

**建议**：至少处理空数组、加载失败占位、标题过长截断；`ariaLabel` 写清楚，键盘可操作的组件别漏焦点态。

## 八、什么时候仍然该用轮播？

物件隐喻不是万能药。下面这些场景，继续用 Swiper / 原生横滑更合适：

*   电商详情里要毫秒级切 50+ 缩略图
*   后台、表单旁的附件预览
*   信息流里强指标驱动的多图卡片
*   设计稿本身就是干净 Banner，没有物件叙事
*   对包体积 / 首屏性能有硬指标，且没有「停留」目标

可以记一张分工表：

| 层级 | 用什么 | 目标 |
| --- | --- | --- |
| 列表层 | 轮播 / 网格 | 效率 |
| 叙事层 | 物件隐喻 | 停留与记忆 |
| 氛围层 | 背景 / 文字动效 | 情绪，不抢交互 |

## 九、性能与移动端：好看之外还要能用

物件感如果以卡顿为代价，用户会立刻退回「这就是个重页面」。几个务实建议：

1.  **按需装包**：上线用 `@cos-design/photo-*`，不要为了一个相册拖进整个视觉库。
2.  **图片本身要瘦**：组件再巧，4K 原图也会拖死；活动页图先压到合适宽度。
3.  **首屏慎用 WebGL**：Three.js 方案延后加载或放到非首屏。
4.  **移动端手势冲突**：横拖类组件（胶卷、卷轴、明信片）注意和页面纵向滚动抢手势；给够高度与触控热区。
5.  **减少同屏 3D**：一屏一个 `preserve-3d` / WebGL 舞台通常更稳。
6.  **记得降级**：低端机或 `prefers-reduced-motion` 时，可退回静态封面 + 简易切换——「能摸」是加分项，不是硬门槛。

## 结语：下次先问「桌上会是什么物件？」

如果只带走三句话，我希望是这三句：

1.  **轮播解决效率，物件隐喻解决停留。**
2.  **叫得出名字、动作对得上、气质配得上。**
3.  **一页 1～2 个高潮物件够了，别整页放烟花。**

接到「图集一定要让人看完」时，可以先问自己：

> **这段如果出现在真实桌面上，它会是什么物件？**

答得出来，交互就有了方向；答不出来，轮播仍然够用。

我把答得出来的那些，收成了可安装组件。打开 Playground 拖两下，往往比再开一轮需求会更快：

*   仓库：[github.com/jiaxiantao/cos-design](https://github.com/jiaxiantao/cos-design)
*   全量包：`cos-design@3.7.3`
